# Rush01（4x4 Skyscrapers）バックトラッキング設計

## 1. 状態定義（何を持てば探索できるか）

### 入力（固定情報）

* `top[4]`：各列を上から見た見える数（col1top〜col4top）
* `bottom[4]`：各列を下から見た見える数（col1bottom〜col4bottom）
* `left[4]`：各行を左から見た見える数（row1left〜row4left）
* `right[4]`：各行を右から見た見える数（row1right〜row4right）

### 盤面（探索対象）

* `grid[4][4]`：各マスの高さ（1〜4）

  * 未確定は `0` などで表す

### 制約管理（高速な重複チェック）

* `row_used[4]`：各行で使われた数字集合（1〜4）
* `col_used[4]`：各列で使われた数字集合（1〜4）
* 実装イメージ：集合は **ビットマスク**（1〜4を4bit）で持つ

  * 目的：候補生成/重複判定を高速化

### 探索の進捗（どこまで決めたか）

* A案：`pos`（0..15）でセルを1個ずつ埋める
* B案：`r`（0..3）で **行ごとに確定**（おすすめ）

  * この問題は「行が1..4の順列」なので、行単位が相性◎

### 候補集合（前処理で強化）

* `row_candidates[r]`：行 r に入りうる **長さ4の順列**の一覧（最大24個）

  * 条件：

    * `visible_from_left == left[r]`
    * `visible_from_right == right[r]`
* これで探索が「行に候補順列を選ぶ」になり分岐が減る

## 2. 関数分割（指定フォーマット）

### 入力・検証

* **関数名:** `parse_clues`

* **目的（責務）:**

  * 引数文字列を分解して `top/bottom/left/right` へ格納
  * '1'〜'4' か、要素数16か、スペース区切り形式かを検証

* **引数:**

  * 引数文字列
  * 出力先 `top[4], bottom[4], left[4], right[4]`

* **戻り値:**

  * 成功/失敗（真偽）

* **関数名:** `basic_clue_sanity_check`

* **目的（責務）:**

  * 明らかに矛盾するヒントを探索前に弾く
  * 例：値は1〜4、4なら単調増加が強制、など

* **引数:**

  * `top/bottom/left/right`

* **戻り値:**

  * 真偽

---

### 見える数の計算・部分チェック（枝刈り）

* **関数名:** `visible_count`

* **目的（責務）:**

  * 長さ4の列から、端から見える箱の数を計算

* **引数:**

  * 配列 `a[4]`（確定済み）
  * 方向（左→右 / 右→左 など）

* **戻り値:**

  * 見える数（1〜4）

* **関数名:** `visible_partial_feasible`

* **目的（責務）:**

  * 途中まで埋まった行/列が、最終的に指定値になりうるか判定（枝刈り）
  * 例：

    * すでに見えている数が `target` を超えたらアウト
    * 残りをどう置いても `target` に届かないならアウト

* **引数:**

  * 途中状態の列（確定＋未確定）
  * 使用済み集合（残り候補推定に利用）
  * 目標 `target`（top/bottom/left/right のいずれか）
  * 方向（上から/下から など）

* **戻り値:**

  * 真偽

> ※4x4なら厳密最適まで不要。
> 「下限（現状で見えてる数）」と「上限（残りで最大いくつ増やせるかの楽観）」で `target` が範囲内かを見るだけでも効果あり。

---

### 行候補（順列）生成

* **関数名:** `generate_all_perms_1to4`

* **目的（責務）:**

  * {1,2,3,4} の順列をすべて生成（24個）

* **引数:**

  * 出力先 `perms[24][4]` 的な領域

* **戻り値:**

  * 生成個数（24）

* **関数名:** `filter_row_candidates`

* **目的（責務）:**

  * 全順列から、行 r の `left[r]` と `right[r]` を満たすものだけ抽出

* **引数:**

  * `perms`
  * `left[r], right[r]`
  * 出力先 `row_candidates[r]`

* **戻り値:**

  * 候補数

---

### バックトラッキング本体（行ごと確定：おすすめ）

* **関数名:** `solve_by_rows`

* **目的（責務）:**

  * 行 r を順に候補順列から選んで盤面を埋める
  * 「最初に見つかった解で停止」

* **引数:**

  * `r`（次に埋める行番号）
  * `grid`
  * `row_candidates`
  * `col_used`
  * `top/bottom/left/right`

* **戻り値:**

  * 解が見つかったか（真偽）
  * ※真なら `grid` が解で埋まっている

* **関数名:** `can_place_row`

* **目的（責務）:**

  * 行 r に候補 `cand[4]` を置けるか判定（枝刈りの中心）
  * 判定内容：

    * 各列 c で `cand[c]` が `col_used[c]` に含まれない（列重複禁止）
    * 置いた結果、各列が `top/bottom` を満たしうる（`visible_partial_feasible`）

* **引数:**

  * 行番号 r
  * 候補 `cand[4]`
  * `col_used`
  * `grid`
  * `top/bottom`

* **戻り値:**

  * 真偽

* **関数名:** `apply_row` / `undo_row`

* **目的（責務）:**

  * `apply_row`：grid更新＋col_used更新
  * `undo_row`：元に戻す（バックトラック）

* **引数:**

  * 行番号 r
  * 候補 `cand[4]`
  * `grid`, `col_used`

* **戻り値:**

  * なし

* **関数名:** `final_check_all_cols`

* **目的（責務）:**

  * 全行が埋まった時点で各列の `top/bottom` を完全一致で確認

* **引数:**

  * `grid`
  * `top/bottom`

* **戻り値:**

  * 真偽

* **関数名:** `print_grid`

* **目的（責務）:**

  * rush01の形式で盤面を出力

* **引数:**

  * `grid`

* **戻り値:**

  * なし

## 3. 手作業ログ（10〜20ステップ）

### 入力例（解がある例）

* `top`    : 3 2 1 2
* `bottom` : 2 2 3 1
* `left`   : 2 2 1 3
* `right`  : 2 2 3 1

### 事前準備

* 24順列から各行 r について

  * `visible(left)==left[r]` かつ `visible(right)==right[r]`
    を満たす順列だけ `row_candidates[r]` に残す

---

### 探索ログ（行ごと確定方式の例：15ステップ）

> 表記：
>
> * 行 r に候補 `cand` を試す
> * 列重複OK?
> * 列 top/bottom 部分可否OK?
> * OKなら確定して次へ、NGなら戻る

1. Start：r=0、`grid` 空、`col_used` 全部空
2. r=0 候補 `cand=[2,1,4,3]` を試す

   * 列重複OK（未使用）
   * 列部分可否OK（見えすぎていない）
   * apply（row0確定）
3. r=1 候補 `cand=[3,4,1,2]` を試す

   * 列重複OK
   * 列部分可否OK（特に col2 の top=1 方向と整合）
   * apply（row1確定）
4. r=2（left=1,right=3）→ 先頭が4の候補に絞られる
5. r=2 候補 `cand=[4,2,3,1]` を試す

   * 列重複OK
   * 列部分可否OK
   * apply（row2確定）
6. r=3（left=3,right=1）→ 末尾が4に絞られる
7. r=3 候補 `cand=[1,3,2,4]` を試す

   * 列重複OK（各列が残り1個に強制されている）
   * apply（row3確定）
8. r==4（全行完了）
9. 最終列チェック

   * col0=[2,3,4,1] → (top=3,bottom=2) OK
   * col1=[1,4,2,3] → (2,2) OK
   * col2=[4,1,3,2] → (1,3) OK
   * col3=[3,2,1,4] → (2,1) OK
10. 解が見つかったので即終了（最初の解のみ）
11. `print_grid` で出力
    12〜15.（もし不一致なら）r=3の別候補→なければr=2へ戻る…が続く

## 実装チェックリスト（最後に確認）

* [ ] 入力を **16個の '1'〜'4'** として正しくパースできている（順序：top→bottom→left→right）
* [ ] `row_candidates[r]` が **left/right 一致の順列のみ**になっている
* [ ] 探索の深さが「行 r を決める」になっている（方針がブレていない）
* [ ] `can_place_row` で最低限これをチェックしている

  * [ ] 列の重複禁止（`col_used`）
  * [ ] 置いた後の列が `top/bottom` を満たしうる（部分可否判定）
* [ ] `apply_row` と `undo_row` が **完全に対称**（更新したものを全部戻す）
* [ ] 全行確定時に `final_check_all_cols` を必ず行う（部分チェックの漏れ防止）
* [ ] 「最初の解で打ち切り」になっている（下から true が返ったら上位も即 return）
* [ ] 出力フォーマット（スペース・改行）が rush01 の要求と一致
* [ ] デバッグ時に追えるログ点を用意

  * [ ] r、試した候補、弾かれた理由（列重複 / 可視不可能）
